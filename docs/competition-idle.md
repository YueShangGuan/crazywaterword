# 跨服比拼日程与主挂机固定日常

所有星期和日期均叠加当前连接的 `serverClockOffsetMs`。动作提交前再次核对日期，因此跨日后不会继续执行昨日限定动作。等待指定星期仍属于已配置的挂机项目，不会因此停止主挂机。

## 设置与迁移

路径相对于 `settings.modules`。新账号默认关闭新增功能，两个金币门槛均为 0。

| 设置 | 允许值 / 含义 |
| --- | --- |
| `island.factory.mondayGuildPriority` | “周一优先联盟募兵”；仅与 `priorityProduce` 同时开启时生效 |
| `guild.order.enabled` | `off` / `always` / `monday`，只约束募兵动作，仍需联盟总开关 |
| `pet.enabled` | `off` / `always` / `tuesday`，约束整个常规宠物模块 |
| `pet.dailyBreedForPass` | “每天培养一只”，位于宠物执行模式下方，独立于普通模式 |
| `antique.activate`、`antique.upgrade`、`antique.suit.activate` | `off` / `always` / `wednesday`，仍需藏品总开关；`upgrade` 显示为“自动升星”，未增加经验升级 |
| `resident.thursdayMinGold` | 位于普通最低金币奖励下方；周四替换 `minGold`，0 不限制金币 |
| `equip.enabled` | `off` / `always` / `friday`，约束收取、制造、加速和分解，沿用原装备配方策略 |

保存接口严格校验各字段自己的枚举。首次读取已保存设置时，相关布尔值一次性转换为 `off/always`；缺少周四金币门槛时复制原 `minGold`，随后原子回写。执行器只处理当前字符串契约。

周一优先级保留需求来源并传递到配方依赖。募兵先分配库存、在产和成品，再处理其他订单与普通补货；缺少部分原料时，已经分配的原料仍为募兵保留。准入阶段不会将同一份库存再次给普通任务。已有在产、自动生产与等待队列保护继续生效，未新增取消或抢占规则。此设置只影响备料，不自动开启募兵交单；其他日期严格恢复保存的来源集合与顺序。

周四使用专用金币门槛，是因为**基地订单日金币奖励越高，比拼积分越多**。经验、禁止材料、作物过滤、次数上限与缺料等待仍生效。特殊订单按 `WorkerSpecOrderCfg` 的实际奖励判断，缺配置时跳过，不套用普通订单估值。

## 主挂机顺序

每日培育补做 → 普通模块及现有任务 → 跨服积分宝箱 → 勇士战令任务积分与档位奖励。

两个固定领奖链不受福利总开关控制；独立模块执行、模块循环和预览不附带这些操作。旧的可选“周战令奖励”任务入口已移除，周抽奖礼包和次数奖保留原调度。

### 每日培育补做

只由 `dailyBreedForPass` 控制。先确认服务端当前周战令周期、`WeekPassTaskCfg` 中“培育海兽”的目标及最新任务状态。已达标、已领取、未开放或缺少任务状态均跳过。

忽略普通宠物模式、培育开关、物种及品质筛选，从当前赛季已开放且对应材料足够的配方中选择最低品质；同品质依次按培育时间、金币成本和配方 ID 排序。只检查真实宠物建筑的队列，满队或缺料下轮重查，不自动领取成熟海兽腾位。请求固定为 `PetBreedRequest {petId, universal:false}`，不用钻石、万能替代材料或加速。

提交前按账号、角色保存意图及原队列任务身份，成功需由新增对应配方队列任务证明。任务身份包含槽位、配方和服务端起止时间，槽位复用不会误判。成功后按校时后的业务日期持久化完成记录；超时、重启先只读核对，无法确认时保留意图并禁止补发，避免战令进度延迟导致重复培育。此每日上限只约束补做，普通宠物培育仍按用户配置执行。

### 跨服积分宝箱

读取 `CrossRankInfoRequest`，需要明确主题、分组等级、已领档位及本角色积分。`CrossRankDailyRwdCfg` 按主题选择最高且不超过分组等级的等级配置，再按积分门槛排序。

有可领档位时发送空的 `GetDailyRewardRequest {}`，明确等待 `GotRewardResponse`。每次领取后重新查询相同主题、分组和业务日期的进度；无论一次合并领取还是需要多次请求，均继续至当前档位领完。分组中、未开放、缺状态、拒绝、进度不增加或结果不确定时结束本链，未决请求保留保护；跨日后重新查询。不领取排行榜结算奖。

### 勇士战令

只处理服务端当前开放周期。逐项领取所有已达配置目标且未领取的任务积分，每项都读回任务领取标记和积分增长。之后重新读取积分及档位，反复领取所有已达标免费权益；`activePay=true` 时同时领取已有付费权益，不购买或激活战令。

每次档位领取后核对具体免费或付费标记；没有进度则停止。未决的空领奖请求会先按旧目标权益只读核对，不能因积分增长、可领列表变化而换一个幂等键重发。日志分别记录任务积分、实际档位和跨服宝箱进度。

## 协议证据与离线验证

抓包证据见 [2026-11-05 抓包分析](capture-analysis-20261105.md)。本次抓包证明跨服空请求能合并领取多档，并证明战令任务积分协议；战令档位协议另外使用当前客户端及协议编解码确认，未将其记作本次抓包发生过的操作。

测试使用隔离临时账号目录及内存网关，双向消息均通过当前协议编解码，覆盖：

- 设置迁移、严格枚举、保存回显、跨日、服务端时差、非执行日保留挂机和旧入口日期限制。
- 募兵与普通需求争用原料、依赖链、未凑齐配方的原料保留、共享库存、自动生产与满队列保护；周四替换门槛、0 值和特殊订单奖励。
- 宝箱合并与分次领取、已领完、缺角色或进度、分组、拒绝、停滞、超时与跨日。
- 多任务积分、多档免费与已有付费权益、未激活付费战令、未决档位恢复及积分变化保护。
- 宠物关闭时补做、任务已完成或缺状态、最低可用品质、成本排序、缺料、队满、重复轮次、槽位复用与重启恢复。
- 实际表单渲染器的下拉选项、值、说明和相邻控件顺序，以及主挂机前后顺序、福利关闭与独立执行隔离。

本次自动化与排产回归 322 项、控制台 43 项通过，224 个请求及 1587 个协议类型核对通过；循环、日常调度和广告商店专项自检通过。完整 `npm test` 仍被既有道具图标覆盖率断言阻断（1059/1207），未修改该断言。

界面使用实际设置渲染器的离线 DOM 检查；本次修改的内嵌脚本不依赖 UI 打包产物，因此未重建已有产物。源代码和离线测试结果不代表已在游戏内验收；本次没有发送真实游戏请求，也没有重启现有服务。
